# 如何做一个个人网站

首先：代码开源在 [GitHub 仓库](https://github.com/p0sty1/portfolio)。你可以直接看这个网站是怎么搭起来的，也可以 fork 一份之后按自己的想法改。

## 准备

### Cloudflare

Cloudflare 在这里主要负责两件事：**部署**和**对象存储**。

部署就是把本地写好的网站发布到公网，让别人可以通过网址访问。对象存储可以理解成一个适合放文件的云端空间，比如图片、视频、博客 markdown、画廊素材等。我这个网站用 Cloudflare Workers 承载页面和接口，用 R2 存放部分图片和内容文件。

### Supabase

Supabase 可以理解成一套更容易上手的后端服务。它的核心是数据库，用来保存动态、留言、喜欢、提问这些需要长期存在的数据。它也提供权限控制，避免所有人都能随便改你的数据。

如果你的网站只是静态展示，可能暂时不需要数据库；但只要你想做留言、发布动态、点赞、提问这种互动功能，Supabase 就会很有用。

### 域名

域名不是必须的，但有一个独立域名会更容易传播你的网站，也更像一个真正属于你的空间。

我的域名是在腾讯云购买的。你也可以在其他平台买，只要后面能把域名解析到 Cloudflare 或你使用的部署平台即可。简单说，域名解析就是告诉互联网：访问这个名字时，应该去哪里找你的网站。

### GitHub 账号

GitHub 用来托管代码。你可以把它理解成一个代码仓库，也是 AI 和部署平台协作的中心。

Cloudflare 可以连接 GitHub，并持续查看你的代码更新。比如你把代码推送到 GitHub 的 `main` 分支，Cloudflare 就可以自动重新构建和部署网站。这样你不需要每次手动上传文件。

### AI 编程工具

我用过 Cursor 和 Codex。强烈推荐直接上好一点的模型，因为个人网站最难的往往不是写某一行代码，而是让 AI 理解你的设计意图、功能细节和修改方向。

如果预算敏感，可以比较不同工具的订阅和用量模式。我的体感是 Codex Plan 更容易控制成本，但具体还是看你的使用频率和项目复杂度。

这里有几个名词需要先认识：

- **Token**：可以理解成服务的钥匙。比如 Cloudflare、Supabase、GitHub 都可能需要 token 授权工具访问。不要把 token 公开写进代码仓库。
- **MCP**：Model Context Protocol，可以理解成 AI 工具和外部服务之间的连接桥。配置好 Supabase、Cloudflare、GitHub 的 MCP 后，你只需要跟 AI 说话，它就可以帮你查数据库、看部署、改代码、读仓库状态。
- **IDE**：写代码的软件。Cursor、VS Code 都是 IDE 或代码编辑器。你不一定要完全会写代码，但最好知道文件、终端、插件、环境变量大概在哪里。

## 个人准备

### 1. 一个 IDEA

先想清楚你的网站想做什么。

我比较 I，不太敢频繁发社交平台，但又希望能分享日常，所以做了这个网站。它不是传统简历页，而是一个更像个人社交主页的空间：可以发动态、放画廊、写博客、收留言、展示喜欢的东西。

你的 idea 不需要很大。它可以是作品集、日记、相册、小游戏合集、读书记录、饭店地图，或者任何你愿意长期维护的小东西。

### 2. 找一个好的教程

小红书或者 B 站都有很多不错的平台教程。你可以先看看别人做了什么项目、用了什么工具、遇到了什么坑。

教程的作用不是让你照抄，而是帮你建立路线感：一个网站通常需要前端、部署、数据库、域名、素材管理这些部分。只要你大概知道项目需要怎么做，剩下的细节交给 AI 会简单很多。

### 3. 配置好 AI 工具

准备好你的 token，也尽量配置好 MCP。尤其是 Supabase、Cloudflare 和 GitHub 这三个。

配置完成后，你就可以像和同学分工一样跟 AI 说话：让它查表、写组件、改 UI、看报错、推代码、重跑部署。你需要做的事情会变成确认方向、同意授权、检查结果，以及不断补充需求。某种意义上，你会变成一个无情的同意和授权机器。

### 4. 不断描述你的需求

最后的最后，就是不断不断地跟 AI 描述你的需求。

一开始说不清楚很正常。你可以先说“我想要一个像社交软件一样的个人主页”，再慢慢补充“移动端要保留底部导航”“动态可以发图片和视频”“博客要更像主题文章”“发布动态前要二级密码”。每一次描述都会把网站往你的想法推近一点。

我的经验是：不要怕反复。网站不是一次生成出来的，而是在很多次修改里长出来的。

## 一个简单流程

1. 想清楚网站的核心 idea。
2. 找几个相似项目或教程，建立大概路线。
3. 准备 GitHub、Cloudflare、Supabase 和域名。
4. 配置 AI 编程工具、token 和 MCP。
5. 让 AI 先搭基础页面，再逐步加功能。
6. 每次修改后本地预览、跑测试、部署到线上。
7. 继续描述，继续修改，继续上线。

做个人网站不一定要先成为程序员。你真正需要的是一个愿意反复表达的脑子，以及一点点把想法落到页面上的耐心。
